# 如何去学习一门新的语言

（注：本文只是本人学习过程中浅薄的理解，作者还会继续学习，使用ChatGPT进行过常识性纠错，有AI成分，请见谅）	

先说在前面，这篇文章不太适合第一次学编程的人。

如果你是理工科的大一学生，那我希望你能好好的上学校开设的C语言或者C++；如果你是文科，但是希望以后想要转业互联网（现在还真有这样的人吗，笑），那我也真心的推荐你从C++或者python开始学起。

也许，很多人认为学习一门语言并搞清楚其中的逻辑就很痛苦了，学习多门语言更是会n个相似的知识相互打架。

我并不是要求你们要做到“精通”两门以上的语言，只是希望你能够拿到一段你所学的语言的代码时，具有立刻看懂其语义的能力，知道变量、函数、类、异步这些东西是什么，知道两门语言在形式上有什么差异，为什么语义要这么设置。	接下来，我会通过Rust这门语言，向你讲解如何进行知识的迁移。下面以我的项目代码举例：

```rust
struct ApiMessage {
    id: String,
    role: String,
    content: String,
    created_at: u64,
    usage: Option<ApiUsage>,
}

fn new_api_message(role: &str, content: String, usage: Option<ApiUsage>) -> ApiMessage {
    ApiMessage {id: new_api_message_id(), role: role.into(), content, created_at: unix_millis(),usage,}
}
```

如果你已经学过面向对象，那么这部分你一定不会陌生，因为这部分首先是一个结构体，用来描述一条消息有哪些字段。它和 C++ 的 struct 很接近；如果使用 Python 来理解，可以暂时把它看成一个只保存数据的对象。

对于只学了C++的同学来说，一定不会陌生，但是在只学了python的同学的眼里，似乎和自己学过的类不一样，因为python的写法是这样的：

```python
class ApiMessage:
    def __init__(self, id, role, content, created_at, usage=None):
        self.id = id
        self.role = role
        self.content = content
        self.created_at = created_at
        self.usage = usage
```

但是，下面的函数呢？这下该轮到只学C++的同学迷糊了，fn是函数定义，()里面的是传入的参数，->后面的一大坨是啥？

python的同学会心一笑，因为Python 也支持类似的返回值类型标注，但它不是必需的，而且通常不会像 Rust 一样在编译阶段强制检查。只不过Python 通常把初始化逻辑写在类的 `__init__` 方法中；Rust 则常见地通过一个独立函数，或者在 `impl ApiMessage` 中定义关联函数来完成类似工作。

而两门语言都学过的同学，阅读起来更是毫无障碍，这正是**随着掌握的语言变得越来越多，学习新的语言的难度也会越来越低**的最形象的证明。

所以，学习一门新的语言的最好的方式就是：**先把代码往自己熟悉的格式去匹配**。程序主体离不开**函数，变量，容器**，编程语言就是将声明词连同这三个一起，打包成人类与机器可读的语言。按照声明词-主体-操作的格式排列组合，最后的落点一定是你所熟知的格式，而你看不懂的部分无非就是像Java那样，int []array和c语言int array[]，又或者是把一部分重复实现打包成一个方法这样的“障眼法”。

接下来回到Rust的那个函数，我们先不急着理解所有符号，只看它完成了什么事情。

它接收三个参数，创建一条 ApiMessage，然后把这条消息返回出去。用 Python 表示，大概是：

```python
def new_api_message(
    role: str,
    content: str,
    usage: ApiUsage | None = None
) -> ApiMessage:
    return ApiMessage(
        id=new_api_message_id(),
        role=role,
        content=content,
        created_at=unix_millis(),
        usage=usage
    )
```

用 C++ 表示，则可以写成：

```c++
ApiMessage new_api_message(
    const string& role,
    string content,
    optional<ApiUsage> usage
) {
    return ApiMessage{
        new_api_message_id(),
        role,
        content,
        unix_millis(),
        usage
    };
}
```

三种写法的外观不同，但它们表达的是同一个概念：**接收一些数据，组装成一个消息对象，再把对象返回。**

这个地方，在语义的理解上最大的差距就是那个‘&’和“optional<ApiUsage>”了。

&str是一段引用，代表只借用一段字符串，不负责销毁它；

而Option<ApiUsage> 表示“可能有 usage，也可能没有”。C++虽然也有相同的写法，但 Rust 会要求你要求你显式选择如何处理，比如：

```rust
match message.usage {
    Some(usage) => {
        // 有用量信息
    }
    None => {
        // 没有用量信息
    }
}
```

所以它比 Python 中直接使用 None 更严格，也比 C++ 中到处使用空指针更安全。这体现出这三种语言的区别：Python 可以让字段在运行时变成任何类型，而 Rust和C++ 在编译阶段就要求结构明确，只不过C++并不会检查后续的处理。

这告诉了我们Rust的一个设计倾向：对“可能不存在”的情况，不要假装它一定存在，而要把这种不确定性写进类型里。

到这里，我们已经完成了一次最基本的迁移。我们可以发现，虽然我们举例的都是每个语言最基本的语法，但是差别背后却是不同语言最底层的区别，这也向我们说明了语言的选用不应当仅仅去看其对于人类的可读可写可理解性，更应当关注其对于具体场景的适用性。
