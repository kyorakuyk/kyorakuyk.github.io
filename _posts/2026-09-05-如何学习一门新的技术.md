# 后AI时代，我是如何去学习一门新的技术的

先说在前面，这篇文章不太适合第一次学编程的人，若你是新手，推荐去读一读我的另一篇文章：《如何学习一门新的语言》

我想讨论的是另一种情况：你已经**学过至少一门语言**，知道变量、函数、类、异步这些东西是什么，算法课可能也上过，甚至打过竞赛，但当你真的想从零做一个东西时，还是会发现自己不知道该从哪里下手。

这也许是每一位初学者，甚至本身就是科班的学生都会经历的一个阶段吧。

现在的就业环境轮动非常的快，市场早已不满足于之前只会写Java的求职者，当然不可否认Java仍旧是目前最主流的语言之一，但是很多项目开始用Rust，Golang等语言重构，企业对于求职者的技术广度有了更严格的需求。

恐怕和大多数大学生一样，在课业范围之内，我所接触到的最复杂的工程项目的技术栈就是Java+Spring Boot。由于是在课业以内，只需要照本宣科，甚至丢给AI。

在618之前，我赶上了电脑涨价之前的最后一波机会，换掉了我那台修了好多次的笔记本，终于可以毫无卡顿的使用Trae和Codebuddy之类的工具做一些好玩的东西出来。

可当我真用vibe coding做出来一些什么的时候，我突然发现坏菜了。

作为一个项目的Owner，我**居然读不懂我自己的项目！**

## 我缺的不是更多的语法

就像我另一篇文章里写的那样，我学习一门新语言有我自己的方法论。

找相似，理解语义，再去分析每种语言独有的特点部分。但是，这种方法论只对“一门语言就是一门技术栈”的情况管用。

相信有一点不会有争议：**只有自己动手敲过代码和仔细去吸收算法内在的逻辑，知识才能内化成你自己的。**所以，大多数人**总觉得应该先把一项技术学会，再开始做项目。**

我也是，所以我的一般流程是：先找教程，看基础语法；然后去 GitHub 找几个项目；项目太复杂，就再补一点框架知识；框架看不懂，再去找视频。然后参考项目，自己试着搭建一个MVP，不会的问AI。

可是不久，我发现，当我不认识的语法其实来自于一个框架，我发现了这一个方法论的弊端：

**语言与框架同时抢占你的“注意力指针”！**

我们可以把不同技术栈抽象为一张“图”，

我们会发现，学习总是是线性的，并且是一种**知识点的遍历**，不同人的学习方法的最大的区别不例外是深搜/广搜，我们只有遍历到两个技术栈的交点，才能进行选择进或者不进。

如果我们将技术栈“画成图”，我们很容易发现：学习的过程，很像是在画一张**“最小生成树”**！

我知道严格来说这根本不是最小生成树，但作为一个学过算法的人，我脑子里确实第一时间冒出了这个东西。

我的项目架构是TypeScript+React+Rust+Tauri，不幸的是，这四种技术栈，我之前都知之甚少。

所以，每当我遇到打通四个链路的接口调用的时候，并不是把四个技术栈结合在一起，而是每个技术栈之间单挂一条边，把四个“最小生成树”连接成弱连通的一个更大的“最小生成树”！

**这相当于是在用O(M+N+X+Y)级别的学习预算，去学习一个复杂度为O(MNXY)级别的项目。**

**学习的时候，知识是一条线；做项目的时候，问题却是一起出现的。**

所以，回到那句话，**之前总觉得应该先把一项技术学会，再开始做项目。**

**但“学会”的边界到底在哪里，其实很难知晓。**

## 不妨把思路逆转过来

自己的项目是最适合自己学习的，即使是你vibe coding出来的。

既然跟不上自己先前的项目，那么不妨新开一个项目；既然线性的学习无法让我们得知全貌，那么我们就“拍平”它，从“高处”看。

我们此前是从技术栈的“根”出发，去“打通”链路；而这次反过来，从一条最小的链路出发，去向根部延申。

现在没人离得开vibe coding，对我们来说，这一阶段最重要的不是证明“这 300 行代码是我亲手敲的”，而是先让我们看到：

**这个东西到底是怎么跑起来的。**

比如一个最简单的操作：

前端点下按钮。

React 捕获事件。

TypeScript 调用 Tauri。

参数从前端传到 Rust。

Rust 执行逻辑。

结果再回到前端。

如果我连这条链都没真正见过，那么这个时候让我单独去理解 invoke、command、serde，它们对我来说都只是一些散着的知识点。

但当一个东西真的跑起来以后，我就有东西可以拆了。

所以，AI目前带给我们最大的学习方法论变革就是，

**当一个东西真的跑起来以后，我就有东西可以拆了。**

它当然是一个程序，但对我们来说，它首先是一具可以被解剖的东西。
